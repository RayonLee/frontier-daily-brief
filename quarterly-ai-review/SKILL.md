# 季度 AI 综合研究

## 目标

把指定季度的原始材料转化为一份新的综合研究，而不是资料汇编。默认交付约 5 万汉字的中文报告（Markdown、DOCX、PDF）、证据索引（XLSX/CSV）；用户需要时另出仅含参考资料的 PDF。所有数量、结论、图表和页数均从当季度材料重新计算，禁止继承上一季度数值。

## 输入与边界

先确认：季度起止日期、原始目录、输出目录、篇幅与格式。未指定目录时使用项目约定的智库与科技学习目录；未明确要求“全部存档”时，只处理目标季度。

- 使用 `<WORKSPACE>`、`<RAW_DIR_A>`、`<RAW_DIR_B>`、`<OUTPUT_DIR>` 等占位符讨论路径，不把本机绝对路径写进技能或公开产物。
- 保留原始档案，不改写来源文本；新增证据使用新的档案编号，不重排旧编号。
- 每季度重新研究，不把上一季度的主线或判断当作新证据。可做跨季度比较，但须标明时期与证据来源。

## 工作流

### 1. 盘点与提取

1. 枚举文本、PDF 和其他文件，统计实际文件数、日期覆盖、文本字符数与缺失项。
2. 补齐 PDF 文本提取，记录提取失败、乱码、空文本和导航噪声。
3. 保存机器可复算的处理日志，区分原始文件数、可检索文本数与独立研究对象数。

### 2. 筛选、去重与登记

1. 用关键词和标题初筛，再按“是否直接研究 AI、是否有实质分析、是否只是导航或重复抓取”精筛。
2. 按 URL、标题、内容指纹和版本关系去重；同一报告的网页、全文与 PDF 只计一个研究对象。
3. 为全部证据保留稳定的内部档案编号，登记题名、机构、日期、类型、主题、原始路径、公开 URL、摘要、复核状态与去重关系。
4. 内部档案编号只用于溯源，**不得直接作为正文引用编号**。

### 3. 主题研读与证据纪律

1. 按模型与推理、智能体、物理世界、基础设施、开放生态、组织劳动、科学智能、安全治理、国际秩序等主题组织阅读；可按当季度材料调整。
2. 优先官方和一手材料。将“企业自报”“智库主张”“本报告判断”分开，保留实验条件、样本、反证和不可推断事项。
3. 重点提取因果链、约束迁移、反馈机制与反转条件，不以发布数量或企业宣传代替趋势判断。
4. 每项独立判断都记录支持证据、反证或边界、下一季度可监测指标。

### 4. 综合与写作

采用“事实证据 → 内在机理 → 发展主线 → 独立判断”的顺序。默认结构：

1. 执行摘要与核心判断。
2. 研究设计、语料画像和证据边界。
3. 总机理与若干机制章节。
4. 综合研判、矛盾条件与情景。
5. 政策和研究议程。
6. 结语。
7. 参考资料。

使用 `assets/report-template.md` 起草，但不机械填满栏目；没有证据支持的章节删除。图表用于解释结构、机制和比较，不用装饰性数字卡片。

### 5. 引用与公开链接

按首次引用顺序从［1］连续编号；同一来源再次引用沿用首次编号。正文引用、完整报告参考资料和独立参考资料必须使用同一映射。文末只列实际引用的独立来源，不列未引用材料。

使用 GB/T 7714—2015 顺序编码制，优先公开 HTTPS 官方链接；本地档案只进入证据索引，不作为最终参考资料的替代链接。两份 PDF 均不写“编列说明”。详细规则见 `references/editorial-and-formatting.md`。

生成或更新映射：

```bash
python scripts/citation_numbers.py <REPORT.md> \
  --map-out <OUTPUT_DIR>/citation_number_map.json \
  --remapped-out <OUTPUT_DIR>/report_numbered.md
```

### 6. 排版与加粗

- 大标题和一级标题：黑体加粗。
- 二级及更低级别标题：楷体加粗。
- 正文：宋体；核心观点句：宋体加粗。
- 英文和数字：Times New Roman，粗体语境使用其 Bold 版本。
- 嵌入有授权的子集字体，不在仓库中提交字体文件。

不得把粗体静默映射回常规字体。若环境缺少中文粗体，采用经过阅读器验证的文本安全方案；不得仅依赖可能造成粘连或乱码的描边。完整规范见 `references/editorial-and-formatting.md`。

### 7. 验收与交付

先运行自动校验，再渲染每一页检查。验收不合格时修复并重跑，不以“文件能打开”代替视觉验收。

```bash
python scripts/validate_report.py \
  --markdown <OUTPUT_DIR>/report_numbered.md \
  --pdf <OUTPUT_DIR>/report.pdf \
  --json-out <OUTPUT_DIR>/validation.json
```

至少检查：连续编号、重复来源复用、参考资料数量、HTTPS 链接、字体与加粗、长链接换行、表格跨页、空白页、孤页、乱码和遮挡。完整清单见 `references/quality-gates.md`。

### 8. 敏感信息检查

发布前逐项确认：

- 不含本机用户名、绝对路径、`file://` 链接、会话标识、内部运行环境路径。
- 不含 API 密钥、令牌、Cookie、私有仓库内容或未经授权的原始材料。
- 不提交原始报告、证据全文、生成的 PDF、字体二进制或个人信息。
- 示例统一使用占位符；历史季度数字和结论不进入通用技能。

## 资源

- `assets/report-template.md`：季度报告结构模板。
- `references/editorial-and-formatting.md`：引用、公开链接、字体和版式契约。
- `references/quality-gates.md`：自动与人工验收清单、常见失败及修复。
- `scripts/citation_numbers.py`：按首次出现生成引用映射，并可重写标记。
- `scripts/validate_report.py`：校验 Markdown 和 PDF 的编号、链接、字体与文本完整性。
